From request to ready

Four steps. One shared understanding.

  1. Make your checklist

    Start a request, set a deadline, and reuse a template when the work comes around again.

  2. Send one link

    Give the client a private link. They can open their list without signing up.

  3. Watch the documents arrive

    See what is missing. Draft reminders, or send them through your configured mail service.

  4. Review and finish

    Check each arrival, ask for a replacement where needed, and close the request when the work is done.

Understand what you are trusting

The files arrive encrypted.
The responsibility stays clear.

A client's browser encrypts document bytes to your practice's key before upload. The server stores the encrypted envelope; your practice opens it in the browser.

Your practice holds the key

The server does not receive the private document key in plaintext. Save your recovery material safely: losing all usable key copies can make your documents unreadable.

Metadata is still visible

Client names, request details, filenames, file sizes and workflow history remain server-visible. This is document-content encryption, with browser and device trust still required.

Evidence before promises

Hosted launch validation, provider arrangements, legal documents and real operational recovery still need founder decisions and verification. No certification or production backup guarantee is claimed here.

Operations and recovery guide

Before you choose

A few useful answers.

Does my client need an account?

No. They open the private link you send, choose their files, and return to the same checklist later. The link is a credential, so it should be shared carefully.

Can Tickmark read the documents?

The server stores browser-encrypted document bytes and does not hold the plaintext practice key. It can still see workflow metadata. Browser/device compromise and the delivered browser code remain part of the trust boundary.

What happens if we lose our key?

Use a saved practice recovery key or another usable member copy. An encrypted export does not recover a lost private key. If every usable copy is lost, the documents can become permanently unreadable.

Can we send reminders?

You can draft and preview reminders. Actual email or SMS delivery requires the relevant provider to be configured by the operator. Bulk messaging retains explicit review and confirmation.

Is there a free trial?

No. The configured hosted Checkout requires payment details and bills immediately. The £49 per month plan is a commercial decision; this page does not open paid signup.

Can we export our data?

Owner-verified export tooling preserves records and encrypted documents for recovery or migration. Decryption still needs your key material. Deletion and backup expiry are separate processes with operational retention limits.

Can I see it working locally?

The repository includes a private, repeatable synthetic-data setup. It creates fictional people, requests and encrypted PDFs for a loopback-only demonstration. See the interactive-demo guide before running it.
